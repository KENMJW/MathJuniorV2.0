# 需求文档：全科核心素养提分系统 V2.0 — 通用理科基础数据层（math-junior-datalayer）

> **Feature**：`math-junior-datalayer`
> **文档定位**：本文档定义「基础数据层 / 数据准备项目」的需求。它是与前端项目（`math-junior-frontend`）平级的独立项目，负责**生产前端消费的数据库**（`math_junior.db` 家族：core / master / sandbox / questions），以及产出这些数据的**上游 skill 工具链**。
> **首个落地学科**：初中数学。但本层的核心目标是产出**通用于所有 K12 理科**（数/理/化/生/科学）的数据生成工具（skill），初中数学是"第一个真实跑通并验证这套工具"的学科。
> **协作方**：架构师（验收/检查方，默认 claude opus 4.6）负责设计、拆任务、定验收标准、做验收；执行方（默认 Antigravity / gemini-flash-3.8）负责实现。模型为可切换的默认配置，非硬约束（见 §D11）。

---

## 1. 背景与定位

### 1.1 两个平级项目 + 一份数据契约
整个「全科核心素养提分系统 V2.0」初中数学模块拆为两个独立平级项目：

| 项目 | 职责 | 本文档关系 |
| :--- | :--- | :--- |
| 前端应用 + 数据消费层（`math-junior-frontend`） | 纯静态 SPA，只读消费 `math_junior.db` | 只读依赖方；其 `design.md §3 上游数据契约（CT-1~CT-8）`、`§4.2 扁平 schema DDL` 是本项目的**交付目标 / 约束** |
| **基础数据层 / 数据准备项目（本项目）** | 生产前端消费的数据库 + 上游 skill 流水线 | 本文档定义 |

两个项目的接口 = 一份数据契约（前端 `design.md` 已内联为 CT-1~CT-8 + §4.2 DDL）。**本项目以该契约为交付目标。**

### 1.2 核心定位：skill 是"通用 K12 理科基础数据生成器"，与运行代码解耦
- skill 是**数据的生产工具**，不是本项目专用，也不随前端运行。
- **skill 只在项目启动阶段跑一次**：用 Antigravity 联网查询 + 大模型配合，把基础数据灌入数据库；灌完后 skill 对运行期不再起作用（除非以后新增题库才唤醒采题 skill）。
- **前端运行 100% 依赖数据库**，不依赖 skill、不联网。数据更新是低频动作。
- 因此 skill 与代码/数据库彻底解耦。skill 的价值在于**通用**：初中数学验证通过后，换 config（年级/学科）即可为初中物理/化学等复用。

### 1.3 通用性原则（本项目的灵魂约束）
本层要产出的是"能通用所有 K12 理科的工具"，通用性建立在**认知结构 / 生产逻辑层**，而非**内容层**：

- **X → Y 抽象**：每个学科都能从教材提炼出考点集合 X；主线集合 Y 由 X 经一个**归纳函数 f** 得到。f 必须显式定义，否则换学科得不到 Y（伪通用）。【详见 §6，f 待用户提供文档后补全】
- **四段/四维认知阶梯**：概念精讲的四段 = **What / Why / How / Model** 四个认知高度，学科无关。任何理科概念都能套这四层。
- **知识点 → 交互模型**：沙盒/实验的生产逻辑 = "用知识点或知识点组合让大模型生成对应的可交互模型"，学科无关；仅"渲染引擎适配"层学科相关。
- 所有 skill 的**输出 JSON 结构是跨学科通用契约**；学科差异隔离到"内容填充 + Prompt 模板 + 引擎适配"层。

### 1.4 内容为王（最高设计原则）
本系统的价值 = **让学生掌握思维原理、学习底层逻辑、提升学科素养，而非题海战术**。因此：

> **④ 内容（考点四段精讲 / 主线精讲 / 母题四维解剖）必须是顶级名师水准。内容质量是本项目的生命线，优先于交付速度。**

现实约束（务实校准）：
- 知识点数量庞大，**人工无法逐条终审**；"是否顶级"人也未必判得准。
- 因此质量**在生成端争取**（精心 Prompt），**验证端只守底线**（挡明显的坏，不评判优劣），**人工只在发现具体问题时定点介入**。
- 验证**不得过严**：部分基础/离散考点本就无法深入到 Model 层，验证器不得因"层浅"判失败（见 §5.3 自适应严格度）。
- **模型选择不属本 spec**：用哪个模型执行/生成/验收，由执行方（Antigravity agent 配置）决定，改 agent 即可切换；本 spec 只定义"要什么质量、怎么验证"，不固化模型。

- 四个经**实测验证**的通用 skill（含修正后的脚本、SKILL.md、Prompt 契约、验证 rubric）。

- **107 考点的内容**（哪 107 个、名称、领域、小类）冻结不动。ID 格式与其它结构字段作为第一层基础数据可重新定义（对齐前端契约）。

## 3. 需求（Requirements）

### 需求 1：① 基础字典生成（skill-genbasicinfo 修正与扩展）
**用户故事**：作为架构师，我需要 skill-genbasicinfo 产出结构正确、字段完整、可喂满 `core.db` 结构层的基础字典，以便前端消费并可复用于其它理科。

#### 验收标准
1. WHEN 修正 `enumerate.py` 的边去重 bug，THEN `edges` 数组与 `meta.total_edges` 去重后为真实边数（初中数学 = 493，非 498）。
2. WHEN 修正组合 ID 编号，THEN `combination_id` 在每个基数内从 1 连续编号（`C3-0001`、`C3-0002`…），无跨基数全局递增，无空洞。
3. WHEN 执行组合有向验证（Step4）真跑，THEN 每个 size≥2 组合获得 `is_valid` 判定、`directed_order`（教学序）、`question_hint`（双语出题思路）、`question_types`。
4. WHEN `is_valid=false`，THEN 该组合被**剔除**，不入库；`is_question_valid` 字段不进 `core.db`；剔除后 `combination_id` 重新连续编号。
5. WHERE 考点 ID，THE 系统 SHALL 统一为带连字符格式 `KP-001`（内容不变）。
6. WHEN 拆分学期，THEN 每个考点由"七年级上"等映射为 `grade`(7/8/9) + `semester`(1/2)（已验证 107 考点 100% 可切分）。
7. WHEN 补充双语，THEN 107 考点均有 `name_en`。
8. WHEN 生成拓扑方向，THEN 每个考点有 `predecessors`/`successors`（前置/后继），供 `knowledge_graph_semesters` 的焦点光束消费。
9. WHERE 12 主线归纳，THE 系统 SHALL 按归纳逻辑 f（§6，待补）产出 `logic_lines` 骨架 + 每考点 `primary_line_id`（单归属）。
10. WHEN 产出 JSON，THEN 其结构为 §4 通用输出契约，可无损映射至 `core.db` 四表结构层字段。

### 需求 2：② 真题库生成（skill-gendb 修正与对齐）
**用户故事**：作为架构师，我需要 skill-gendb 采集真题并**直接产出前端扁平 schema**，避免"打包 JSON → 二次 ETL"的双重转换，且难度算分可信、图文对齐。真题来源由我人工投喂。

#### 验收标准
0. WHERE 真题来源，THE ② 真题 SHALL **由用户人工投喂来源**（网址/本地文件路径，可多个）。系统在每批采集**执行前**进入**输入停靠点**（见 §5.4），提示用户输入来源，收到后才开始采集。**系统不得自行搜索/臆测真题来源。**
1. WHEN skill-gendb 入库，THEN 直接产出前端 `questions` 扁平列结构（`stem_zh/stem_en/options_json/answer_standard/...`），不产"打包 JSON 大字段"。
2. WHERE 字段命名与枚举，THE 系统 SHALL 对齐契约：`question_type ∈ {single_choice,fill_blank,solution}`（非中文枚举）；`difficulty_level` 为整数 1~9（非 "L1" 字符串）；`primary_point_id`/`combination_id` 用 `KP-`/`C` 连字符格式。
3. WHEN 匹配 combination_id，THEN 在①产出的"可出题组合白名单"中查表（`sorted(kp_ids)`）；查不到判越界丢弃。
4. WHEN L1-L9 算分，THEN 通过**金标校准**验证（见需求 7）：抽样人工标定难度与双引擎算分对比，达标率满足阈值。
5. WHEN 图文分离，THEN "如图"关键词与图片数差值 > 2 的题按 SKILL 规则丢弃；图片路径写入 `image_paths_json`。
6. WHEN 采集报告输出，THEN 含处理总数/成功入库/无效丢弃/越界丢弃/成功率。

### 需求 3：③ SVG 资产生成（skill-gensvg 新建）
**用户故事**：作为架构师，我需要每个考点一张合规的双语示意图，且生产流水线通用于其它理科。

#### 验收标准
1. WHEN 生成 SVG，THEN 每个考点产出 `zh`/`en` 两版，路径写入 `svg_asset_zh`/`svg_asset_en`。
2. WHERE 合规校验（机器，学科无关），THE SVG SHALL 不含 `<foreignObject>`（属性 P20）、含合法 `viewBox`、数学/学科符号矢量路径化、无脚本。
3. WHEN 合规校验不通过，THEN 回炉重生成，脏 SVG 不入库。
4. WHERE 正确性（"图是否正确表达了该考点"），THE 系统 SHALL 依赖**人工教研抽检**（机器不判专业正确性）；抽检不合格定点回炉。
5. WHERE 流水线，THE 生成+校验机制 SHALL 学科无关；仅"学科示意图 Prompt 模板"为外挂、学科相关。

### 需求 4：④ 内容生产（skill-gencontent 新建 · 内容为王）
**用户故事**：作为架构师，我需要顶级名师水准的四段精讲/主线精讲/母题四维解剖，教学生思维原理而非题海。母题由大模型基于经典题型生成，与真题库独立。

#### 验收标准
0. WHERE 母题来源，THE 119（通用为 |X|+|Y|，见 §6-数量）母题 SHALL **由大模型基于经典题型自主生成**（输入 = 考点/主线/组合结构），**不依赖 ② 真题库、不需要人工投喂网址**。母题 `source` 字段记录"仿照的题型出处/风格"，非实际抓取来源。
0a. WHERE 母题数量（通用），THE 母题总数 SHALL = **考点母题数 |X|（每考点 1 道 `point_master`）+ 主线母题数 |Y|（每主线 1 道 `line_master`）**。初中数学实例 = 107 + 12 = 119。数量由 ① 产出的 X、Y 派生，不写死。
0b. WHERE 两类母题定位，THE **考点母题** SHALL 为"教单个考点的标准标杆题"（难度适中）；**主线母题** SHALL 为"考这条主线的压轴综合题"（高难，`empirical_scoring_rate ∈ [0.15,0.35]`）。
1. WHERE 认知结构，THE 四段/四维 SHALL 遵循 **What / Why / How / Model** 通用阶梯：
   - What（是什么·直观本质）、Why（为何·原理由来）、How（怎么用·严格方法·**恒必填**）、Model（变式建模迁移）。
2. WHERE 自适应深度，THE 系统 SHALL 遵循"能深必深，但不强行深"：大考点（几何/函数/圆等）四层做满；基础/离散考点（科学记数法、同类项等）允许 Model 层薄或缺，How 层恒必填。
3. WHEN 生成内容，THEN 使用精心 Prompt（名师视角、好坏对照样例、"教思维不教套路"硬约束）。（用哪个模型由执行方 agent 配置决定，不在本 spec 固化）
4. WHERE 质量验证（守底线，不评优，见 §5.3），THE 系统 SHALL 仅拦截四类"坏"：空洞堆结论 / 幻觉 / 公式错误 / 该讲原理处偷懒；不因"层浅"判失败。
5. WHEN 任一生成内容含公式，THEN 必须通过数学门神 `sanitize_and_verify_math()` 清洗，脏公式绝不入库（对齐前端 §6.1 / 属性 P21）。
6. WHERE 主线精讲，THE 系统 SHALL 由"考点四段（微观）向上归纳为主线四段（宏观）"，输入含主线所辖考点及其四段。【依赖 §6 主线逻辑 f】
7. WHERE 母题四维，THE `dim3`（How/严密）SHALL 恒必填；几何/函数大考点母题维度 ≥ 3（对齐 CT-6）。
8. WHERE 母题物理隔离，THE 母题入 `master_examples`，绝不混入 `questions`（对齐 CT-8 / 属性 P17）。

### 需求 5：沙盒 / 实验模型生产（④ 子项 · 通用抽象 + 引擎适配）
**用户故事**：作为架构师，我需要沙盒配置的生产逻辑通用（数学=模型、物理=实验），仅引擎适配层学科相关。

#### 验收标准
1. WHERE 生产逻辑，THE 系统 SHALL 以"知识点/知识点组合 → 大模型生成抽象交互模型描述（可拖动对象/可变参数/展示的不变量或守恒量）"为通用中间层。
2. WHEN 适配渲染，THEN 抽象描述经"引擎适配层"转为具体引擎配置：数学 → JSXGraph 声明式 JSON；其它学科 → 各自仿真引擎（引擎适配层学科相关）。
3. WHERE 前端契约，THE 数学沙盒最终产出 SHALL 填满 `concept_sandboxes`/`leap_sandbox_models` 的声明式字段（`viewbox_spec_json`/`drag_points_json`/`param_sliders_json`/`invariants_display_json` 等）。
4. WHERE 概念沙盒选点（缺口1），THE 系统 SHALL 明确"哪些考点建概念沙盒"（约 40~50 个，非全部 107；`knowledge_points.sandbox_id` 可空⇒渲染占位卡）。选点规则：优先适合可视化交互探究的考点（几何/函数/数轴类）。选点清单为 ④ 沙盒生产的前置决策产物。
5. WHERE 跃迁模型清单（缺口2），THE 36 个 `leap_sandbox_models` 与每条主线的 `flagship_model_id`（旗舰模型）SHALL 以"实验室二手册"（12 主线旗舰 + 36 模型四维变式）为来源，结构化转为 sandbox.db 数据。数量按学科手册定义，非硬编码 36。

### 需求 6：数据一致性与契约对齐
**用户故事**：作为架构师，我需要消除历史数据矛盾，产出与前端契约严格对齐的数据库。

#### 验收标准
1. WHEN 边数口径，THEN 统一为去重后真实边数（493），修正历史文档"493 对被误标为边数"的表述。
2. WHERE 组合基数，THE `kp_count` SHALL 支持 1~8（对齐 CT-2，禁硬编码上限 4）。
3. WHERE 数据库命名，THE 全项目 SHALL 统一 `math_junior.db` 家族（core/master/sandbox/questions）。
4. WHERE ID 规范，THE 系统 SHALL 对齐前端 §11.2：考点 `KP-023`、组合 `C3-0112`、母题 `ME-KP023`/`ME-LINE-A4`、沙盒 `SB-KP023`、模型 `LM-9A-19`。
5. WHERE core.db 内容层 NOT NULL 字段（四段精讲等）在结构阶段尚未生成时，THE 建库脚本 SHALL 填合规占位（由④阶段 UPDATE 覆盖），保证 core.db 可建、可被前端 mock 消费。
6. WHERE `module_name`（缺口4·`knowledge_graph_semesters`），THE 取值 SHALL 明确来源：默认取该考点的 `subcategory`（二级小类），若有更细的教材章节模块划分则用之；`node_id` 按 `NODE-{grade}-{semester}-{KP编号}` 规则生成。
7. WHERE `is_milestone`（缺口5·里程碑考点），THE 判定规则 SHALL 明确：里程碑 = 该主线的关键枢纽考点（被多组合/多后继依赖的大考点，如勾股、二次函数）。由 ① 按"出度/被组合引用次数 + 大考点"规则标定。
8. WHERE `empirical_scoring_rate`（缺口6·主线母题经验得分率），THE 因无真实统计数据，SHALL 由大模型按压轴题难度**估算**一个 ∈[0.15,0.35] 的值，并在数据/文档中**标注为"模型估算值"**，不冒充真实统计。

### 需求 7：L1-L9 难度算分金标校准
**用户故事**：作为架构师，我需要验证双引擎算分的可信度，而非盲信脚本输出。

#### 验收标准
1. WHEN 校准，THEN 抽取 30~50 道人工标定"金标难度"的真题，与双引擎算分对比。
2. WHERE 达标线，THE 算分结果落在金标 ±1 级内的比例 SHALL ≥ 80%（阈值可在验收时依实况调整）。
3. WHEN 达标率低于阈值，THEN 调整算分权重（结构广度分/认知深度分）后复校。

### 需求 8：协作与验收机制
**用户故事**：作为架构师，我需要一套可控、可实测、防失控的执行-验收闭环。

#### 验收标准
1. WHERE 执行架构，THE 系统 SHALL 采用 "执行方（agent）执行 → 验收方（agent）按 rubric 验收 → 通过则放行下一段 / 不通过打回重做" 的自动循环。
   - **默认模型配置（当前轮次记录，非 spec 硬约束）**：数据执行方 = `gemini-flash-3.8`；验收/检查方 = `claude opus 4.6`。
   - 模型可随时由 Antigravity agent 配置切换（改 agent 即可），本 spec 不固化模型，仅记录当前默认配置以便追溯。
2. WHERE 验收标准，THE 每段 SHALL 配**写死的 rubric/checklist**（含机器可对照的实测硬项），验收标准不得临场漂移。
3. WHERE 实测铁律，THE 验收 SHALL 实际跑数据/查数据（如边数=493、combination_id 无重复、字段真非空），**不以执行方自报"测试全绿"为准**。
4. WHERE 熔断护栏，THE 同一验收闸回炉 SHALL 设上限（默认 3 次）；超限即停，把"卡点+原因"抛给用户决策，禁止无限循环。
5. WHERE 分段停靠，THE 任务链 SHALL 按验收闸分段（段1 ①→段2 ②→段3 ③→段4 ④），每闸不过不放行下一段。
6. WHERE 台账，THE 每批交付 SHALL 记入 `ACCEPTANCE_LOG.md`（沿用前端格式：实测明细/缺陷编号/隐患/门禁决定）。
7. WHERE 两类停靠点，THE 任务链 SHALL 区分：
   - **输入停靠点（执行前）**：agent 停下等用户提供外部数据源。**仅 ② 真题采集**需要（每批投喂真题网址/文件，可多个）。①③④ 不需要（均由 ① 的考点数据 + 大模型内部生成）。
   - **验收停靠点（完成后）**：每段末尾 agent 停下等验收，通过才放行。
   - 12 主线归纳/主线精讲段额外依赖用户提供的"主线合并逻辑 f 文档"（§6），文档到位前该段挂起，不阻塞其余段。

## 5. 质量与验证策略

### 5.1 质量哲学（④ 内容）
**质量在生成端争取（顶级模型 + 精心 Prompt），验证端只做底线守门（挡坏，不评优），人工只定点介入。**

### 5.2 生成端（主战场）
- **Prompt 是本 spec 可控的主杠杆**：名师视角、What/Why/How/Model 结构强制、"顶级 vs 平庸"对照样例、"教思维原理不教套路"硬约束。
- 模型选择不在本 spec 固化（由执行方 agent 配置决定，改 agent 即可切换）。

### 5.3 验证端（守门员，不是评委，自适应严格度）
- **规则层（确定性）**：公式过门神；字段存在性；无偷懒词（"综上""略"）；引用考点/公式在字典内。
- **LLM-judge 层（独立模型）**：仅拦截四类坏——①空洞堆结论、②幻觉、③公式错、④该讲原理处偷懒。低于阈值自动回炉。
- **自适应严格度**：大考点查四层；基础/离散考点**不强求 Model 层**，How 恒必填；**层浅不判失败**（验证不得过严，避免逼模型硬凑）。
- **人工**：不做全量审；仅在使用/抽检中发现具体问题时定点回炉。
- **rubric 可复用**：数学 rubric 定好后，换学科改几条即可（服务通用性）。

### 5.4 输入停靠点（人工投喂外部数据源）
- **仅 ② 真题采集需要**：真题来源不可由 agent 臆测，必须用户人工投喂。每批采集**执行前** agent 停下，提示"请提供本批真题来源（网址/本地文件，可多个）"，收到后才采集。
- ①③④ **不需要**输入停靠：① 从 107 考点归纳/枚举；③ SVG、④ 母题/精讲/沙盒均由大模型基于 ① 的考点数据自主生成，不依赖外部投喂。
- 与"验收停靠点"区别：输入停靠在**执行前**（等数据进来），验收停靠在**完成后**（等验收放行）。

### 5.5 产出数量目标（通用公式，非硬编码）
设 |X| = 考点数、|Y| = 主线数。所有产出数量表达为 X、Y 的函数，换学科自动成立：

| 产出 | 通用数量 | 初中数学实例 |
| :--- | :--- | :--- |
| 考点 | \|X\| | 107 |
| 主线 | \|Y\| | 12 |
| 考点母题（point_master） | \|X\|，每考点 1 道 | 107 |
| 主线母题（line_master） | \|Y\|，每主线 1 道 | 12 |
| **母题总数** | **\|X\| + \|Y\|** | **119** |
| 考点四段精讲 | \|X\| 组 | 107 |
| 主线四段精讲 | \|Y\| 组 | 12 |
| SVG 资产 | \|X\| × 2（zh/en） | 214 |
| 概念沙盒 | 选点子集（约 40~50，≤\|X\|） | ~40-50 |
| 跃迁模型 | 按学科手册（数学=36） | 36 |
| 组合 | 团枚举后剔除不可出题（≤ 全枚举数） | ≤2205 |

> 执行方须按此数量交付，验收方按此核对"是否产全"，防止漏产。

## 6. 主线归纳逻辑 f（X → Y · 已定稿）

> **状态：已定稿。f 全自动（prompt + 模型），无人工复核归类（因维度标准因人而异，人工复核不可行）。数量不写死，由 domain 数 + 各 domain 内谱系分支数派生（数学恰好 = 12）。**

### 6.1 f 的两步结构
```
f(X) → Y:
  Step-1 归档: 按 domain(课程分类/领域,教材提炼考点时自带) 把考点分入若干大类。
  Step-2 谱系分支: 在每个大类内,按【该学科范式族的底层逻辑维度词表】切分主线。
  Y = 各大类切出的主线之和。
```

### 6.2 范式族路由（agent 逻辑分支，按输入学科判定）
skill 通用机制不变（domain 归档 → 底层逻辑分支 → Y）；**唯一学科相关的是"底层逻辑维度词表"，按输入学科路由**：

| 范式族 | 适用学科 | 底层逻辑维度词表（Step-2 切分依据） |
| :--- | :--- | :--- |
| **族A 数理范式** | 数学、物理、化学 | **公理/定律** · **结构/形式** · **变换/不变量** · **度量/定量** · **数据/推断** |
| **族B 描述范式** | 生物 | **构成层次** · **规律机制** · **过程功能** |

- 数学（族A）实例：公理层(A1实数/G1欧氏)、结构层(A2式/A3方程/A4函数/G2全等)、变换层(G3四边形演化/G5刚体变换)、度量层(G4圆度量/G6三角)、数据层(S1统计/P1概率) = 12 条 ✅
- **单归属**：一个考点可能跨维度，`primary_line_id` 取**最主导维度**（prompt 内定优先级：可作公理/定律者优先 → 结构 → 变换 → 度量 → 数据；族B：构成 → 机制 → 过程）。

### 6.3 通用边界（K12 理科）
- **本 skill 覆盖**：数学/物理/化学（族A）+ 生物（族B）—— 判据 = "知识点会耦合出题 + 难度可结构化算分"。
- **未来可选扩展点**（本期不实现，设计留接口）：自然地理→族A；小学科学→族B。
- **明确不在范围**：语文/英语/历史/政治/人文地理等文科——它们不满足"知识点组合出题 + L1-L9 算分"前提，应另立独立 skill（见 §D18~D20）。

### 6.4 全自动保证
- Step-1、Step-2 均由 prompt + 模型完成，不设人工复核归类环节。
- 质量靠 §5.2 生成端（精心 prompt）+ §5.3 验证端（守底线）保证。
