## 二、 模块一、二、四题目生成核心逻辑漏洞审查

### 2.1 模块四（实战测评 · 智能组卷中心）两大致命漏洞

#### 漏洞 ①：伪随机种子常数锁死（Seed Hardcoding to `1234567`）
* **代码定位**：`src/modules/exam/drawQuestions.ts` 第 56 行与 `PaperWorkbench.tsx` 第 323 行
* **缺陷机制剖析**：
  在 `PaperWorkbench.tsx` 中调用抽题引擎时：
  ```typescript
  // PaperWorkbench.tsx
  const paper = await drawQuestionsFromDb(dbClient, currentConfig, {
    titleZh: paperTitle,
    fullScore: spec.totalScore,
    timeLimitMinutes: spec.timeLimitMinutes,
    // seed 参数完全缺失！
  });
  ```
  进入 `drawQuestions.ts` 内部后：
  ```typescript
  // drawQuestions.ts 第 56 行
  function shuffleArray<T>(array: T[], seed?: number): T[] {
    let s = seed !== undefined ? seed : 1234567; // 种子硬编码固定死！
    for (let i = arr.length - 1; i > 0; i--) {
      s = (s * 16807 + 11) % 2147483647; // 线性同余发生器 (LCG)
      const j = Math.floor((s / 2147483647) * (i + 1));
      [arr[i], arr[j]] = [arr[j], arr[i]];
    }
  }
  ```
* **实测后果**：
  由于种子 `s` 恒等于 `1234567`，无论用户是在今天还是明天、连续点击多少次“生成试卷”，LCG 算出的排列序列绝对固定。**生成的所有试卷题目完全一模一样，随机性彻底为零**。

#### 漏洞 ②：L1~L5 难度波浪滑块权重完全未接入抽题引擎（纯视觉摆设）
* **代码定位**：`src/modules/exam/drawQuestions.ts` 全局
* **缺陷机制剖析**：
  在 `PaperConfig` 中声明了 `difficultyDistribution: [d1, d2, d3, d4, d5]`。然而在 `drawQuestions.ts` 源码中全局检索 `difficultyDistribution` 或 `weight`，**有效匹配数严格为 0**！
  抽题引擎唯一做的是在抽完之后执行简单的排序：
  ```typescript
  selected.sort((a, b) => a.difficulty_level - b.difficulty_level);
  ```
* **实测后果**：
  用户无论将难度滑块拉到“极简基础”还是“压轴突破”，抽出的题目没有任何区别。难度滑块完全脱钩，未起到任何筛选与加权分配作用。

### 2.2 模块一（探本溯源 · 概念精讲）两大逻辑漏洞

#### 漏洞 ①：进场静态死序，死代码未被调用
* **代码定位**：`src/ConceptNav.tsx` 第 350 行
* **缺陷机制剖析**：
  初次加载单点快练题目时，SQL 查询写死为：
  ```sql
  SELECT * FROM questions 
  WHERE primary_point_id = ? AND question_type = 'single_choice' 
  ORDER BY difficulty_level ASC, question_id ASC
  ```
  在 `QuickPractice.tsx` 第 62 行中直接截取前 3 题：`if (initialQuestions) return initialQuestions.slice(0, 3)`。
  这导致学生第一次打开任何考点时，**看到的永远是题库里 ID 最小的前 3 题，毫无随机性**。
  而在 `quickPractice.machine.ts` 中专门编写的带随机功能的 `fetchQuickPracticeFromDb`（第 182 行），在全工程中从未被引入或调用，沦为死代码。

#### 漏洞 ②：`sort(() => Math.random() - 0.5)` 伪随机算法偏倚
* **代码定位**：`src/modules/concept/quickPractice.machine.ts` 第 140 行 `defaultPicker`
* **缺陷机制剖析**：
  ```typescript
  export function defaultPicker<T>(items: T[], count: number): T[] {
    const shuffled = [...items].sort(() => Math.random() - 0.5); // 经典反模式
    return shuffled.slice(0, count);
  }
  ```
  现代浏览器 V8 引擎的 Timsort 算法要求比较函数满足严格弱序。返回随机负值会破坏排序树状态，导致数组首尾两端的题目被抽中的概率显著高于中间题目，无法达成真正的等概率独立随机。

### 2.3 模块二（经纬纵横 · 思维图谱）两大逻辑漏洞

#### 漏洞 ①：未分层抽样，大考点吞噬小考点
* **代码定位**：`src/modules/graph/GraphNav.tsx` 第 339 行
* **缺陷机制剖析**：
  ```sql
  SELECT * FROM questions 
  WHERE primary_point_id IN (${placeholders}) AND question_type = 'single_choice' 
    AND difficulty_level BETWEEN 4 AND 6 
  ORDER BY RANDOM() LIMIT 20
  ```
  一条主线通常涵盖 6~12 个考点。直接执行 `LIMIT 20` 时，题库中题目较多的大考点（如勾股定理、相似三角形）会天然占据绝大部分配额，导致整条主线的综合测评偏向单一考点，缺乏谱系覆盖均匀度。

#### 漏洞 ②：跨模块共用去重池导致去重频繁失效
* **代码定位**：`src/store/sessionStore.ts` 第 14 行与 `LineQuickPractice.tsx` 第 54 行
* **缺陷机制剖析**：
  模块一与模块二共用单一的 `presentedIds` 集合。学生在模块一刷过的题目会直接影响模块二的候选池；反之亦然。池子迅速低于 3 题，触发强制重置 `clearPresentedIds()`，导致去重状态机频繁失效。

## 四、 实现“题目最大化不重复”的算法重构设计

为了彻底解决“连续刷题/连续组卷 5~10 套题目完全一样”的问题，构建如下三层防重复与加权抽样引擎：

```
                       【全量候选题目集合 (Candidate Pool)】
                                       │
                                       ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │ 第一层：会话滚动衰减去重过滤器 (Session Sliding Window Filter)         │
    │  - 排除最近 N 套试卷 / 最近 K 次练习做过的题目 (权重设为 0)            │
    │  - 若剩余题目不足，按“做过次数”升序惩罚加权 (最小频次优先原则)        │
    └──────────────────────────────────┬──────────────────────────────────┘
                                       │
                                       ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │ 第二层：考点均衡与当期优先分层桶 (Stratified Knowledge Bucket)       │
    │  - 考点均匀覆盖：每个勾选考点至少保证 1 题配额 (Round-Robin 轮转)      │
    │  - 年级学期倾斜：当期学期占 65%，历史跨学期占 35%                     │
    └──────────────────────────────────┬──────────────────────────────────┘
                                       │
                                       ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │ 第三层：真实难度波浪联动加权抽样 (Weighted Ripple Reservoir Sampling)│
    │  - 真实读取 L1~L5 权重 [w1, w2, w3, w4, w5] (归一化概率密度函数)      │
    │  - 采用真随机熵种子 (Crypto.getRandomValues / 时间戳毫秒哈希)        │
    │  - 标准 Fisher-Yates 洗牌输出                                       │
    └──────────────────────────────────┬──────────────────────────────────┘
                                       │
                                       ▼
                        【输出：最大化不重复的工整试卷】
```

### 核心算法公式

#### 1. 动量衰减出现惩罚权重（Min-Frequency Penalty）
为了确保在题库被完整做完一遍前绝不重复、做完后均匀轮换，赋予题目抽取权重：
$$W(q) = \frac{1}{1 + \alpha \cdot \text{TimesAppeared}(q)} \times \beta^{\text{Recency}(q)}$$
* $\text{TimesAppeared}(q)$：当前会话中该题目被抽中展示过的总次数（初始为 0）；
* $\text{Recency}(q)$：距离上一次展示相隔的试卷套数；
* **效果**：优先抽取全新未见题目；题库轮空时，自动挑选“距离现在最久远、做过次数最少”的题目，消除题目扎堆死锁。

#### 2. 真实响应的难度配额计算（Hamilton-Hare 最大余数法）
设用户在前端拖拽的难度滑块配比为 $D = [w_1, w_2, w_3, w_4, w_5]$（满足 $\sum w_i = 1$），题型总需求题量为 $N_{\text{req}}$。各难度目标题量计算如下：
$$N_i = \lfloor N_{\text{req}} \times w_i \rfloor$$
未分配名额 $\Delta N = N_{\text{req}} - \sum N_i$，按小数余数 $R_i = (N_{\text{req}} \times w_i) - N_i$ 从大到小降序补足，保证**难度分布严格与用户滑块 100% 严密对齐**。

#### 3. 真随机熵注入与标准 Fisher-Yates 洗牌
废除写死的 `1234567`，改用现代密码学安全随机熵：
```typescript
export function secureShuffle<T>(array: T[]): T[] {
  const arr = [...array];
  const getRandomFloat = () => {
    if (typeof crypto !== 'undefined' && crypto.getRandomValues) {
      const buf = new Uint32Array(1);
      crypto.getRandomValues(buf);
      return buf[0] / (0xffffffff + 1);
    }
    return Math.random();
  };

  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(getRandomFloat() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

### 5.2 战役 B（模块一 · 概念快练）：初态真随机与纯真题三级平滑补齐

#### 步骤 1：在 `ConceptNav.tsx` 中建立纯真题三级漏斗查询
重构 `loadPractice` 函数，淘汰 `ORDER BY question_id ASC` 静态查询，引入三级真题阶梯：

```typescript
// src/ConceptNav.tsx
async function loadPracticeWithThreeTierFallback(point: KnowledgePointRecord) {
  try {
    // 【第一级】：本考点基础真题 (L1~L3) 随机抽样
    let rows = await dbClient.query<any>(
      'questions',
      `SELECT * FROM questions 
       WHERE primary_point_id = ? AND question_type = 'single_choice' AND difficulty_level BETWEEN 1 AND 3
       ORDER BY RANDOM() LIMIT 3`,
      [point.point_id]
    );

    // 【第二级】：若不足 3 题，从本考点进阶真题 (L4~L5) 补足差额
    if (rows.length < 3) {
      const needed = 3 - rows.length;
      const existIds = rows.map((r: any) => r.question_id);
      const placeholders = existIds.map(() => '?').join(',');
      const excludeClause = existIds.length > 0 ? `AND question_id NOT IN (${placeholders})` : '';

      const tier2Rows = await dbClient.query<any>(
        'questions',
        `SELECT * FROM questions 
         WHERE primary_point_id = ? AND question_type = 'single_choice' AND difficulty_level BETWEEN 4 AND 5 ${excludeClause}
         ORDER BY difficulty_level ASC, RANDOM() LIMIT ?`,
        [point.point_id, ...existIds, needed]
      );
      rows = [...rows, ...tier2Rows];
    }

    // 【第三级】：若仍不足 3 题，从同主线 (primary_line_id) 相邻考点真题中借调
    if (rows.length < 3) {
      const needed = 3 - rows.length;
      const existIds = rows.map((r: any) => r.question_id);
      const placeholders = existIds.map(() => '?').join(',');
      const excludeClause = existIds.length > 0 ? `AND q.question_id NOT IN (${placeholders})` : '';

      const tier3Rows = await dbClient.query<any>(
        'questions',
        `SELECT q.* FROM questions q
         JOIN knowledge_points kp ON q.primary_point_id = kp.point_id
         WHERE kp.primary_line_id = ? AND q.question_type = 'single_choice' ${excludeClause}
         ORDER BY q.difficulty_level ASC, RANDOM() LIMIT ?`,
        [point.primary_line_id, ...existIds, needed]
      );
      rows = [...rows, ...tier3Rows];
    }

    return mapRawRowsToQuestions(rows);
  } catch (err) {
    console.warn('[loadPractice] Fallback error:', err);
    return [];
  }
}
```
