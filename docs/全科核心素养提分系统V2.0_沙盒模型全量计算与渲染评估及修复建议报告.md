## 一、 执行摘要与跨模块同源性结论

### 1.1 架构单一真实源（SSOT）确认
经对全系统前端数据流与组件实例化链路的静态分析与运行时追踪，**模块一（探本溯源·概念精讲）、模块二（经纬纵横·思维图谱）、模块三（见微知著·实验探究）对应的所有沙盒模型，在底层严格遵循单一真实源（Single Source of Truth, SSOT）架构**：

```
                       【底层单一真实源 (SSOT)】
            ┌──────────────────────────────────────────┐
            │  ① 数据库: data/sandbox.db (两个物理表)  │
            │     - concept_sandboxes (46 考点沙盒)    │
            │     - leap_sandbox_models (37 跃迁沙盒)  │
            │  ② 动力学数学引擎: morphControllers.ts    │
            │  ③ 遥测与公式引擎: invariants.ts          │
            │  ④ 统一黑板渲染器: SandboxRenderer.tsx    │
            └──────────────────────────────────────────┘
                                   │
         ┌─────────────────────────┼─────────────────────────┐
         ▼                         ▼                         ▼
   【模块一：概念精讲】      【模块二：思维图谱】      【模块三：实验探究】
     (ConceptNav.tsx)          (GraphNav.tsx)          (LabWorkspace.tsx)
         │                         │                         │
         ├─► 考点沙盒轨            │                         ├─► 实验室一 (考点沙盒)
         │   (LinkedSandboxSlot)   │                         │   (复用 SandboxRenderer)
         │   (读 concept_sandboxes)│                         │   (读 concept_sandboxes)
         │                         │                         │
         │                         ├─► 跃迁旗舰沙盒轨        ├─► 实验室二 (跃迁沙盒)
         │                         │   (复用 LeapLab)        │   (复用 LeapLab)
         │                         │   (读 leap_sandbox_models)│ (读 leap_sandbox_models)
```

### 1.2 全局修改联动性
* **模型一联动**：模块一内嵌的精讲沙盒（`LinkedSandboxSlot`）与模块三实验室一（`LabWorkspace`）读取相同的 `concept_sandboxes` 表，均交由 `<SandboxRenderer>` 渲染。**修改渲染器或数据表，模块一与模块三 100% 自动同步更新**。
* **模型二联动**：模块二知识谱系的“链接沙盒”Tab 与模块三实验室二均直接实例化同一个 `<LeapLab>` 组件，由 `morphControllers.ts` 纯数学引擎驱动，全局状态记录于 `useSessionStore`。**修改解算器或跃迁配置，模块二与模块三 100% 自动同步更新**。

## 三、 核心严重缺陷深度剖析与实测复现

### 3.1 `LM-7A-01`：动点滑块逻辑阻断、数据与画布脱节、拖拽松手回弹
* **代码定位**：`src/modules/sandbox/morphControllers.ts` 第 724 行与第 1970 行
* **缺陷机制**：
  1. `solveLM7A01` 中对动点 $P$ 的更新被包裹在 `if (params.param_t === undefined && params.pos_p !== undefined)` 中。而系统初始状态下 `param_t` 默认初始化为 `5.0`，导致此条件恒为 `false`，滑块 `pos_p`（动点坐标，-8 ～ 8）被逻辑阻断；
  2. 调度器第 1970 行硬编码排除了该模型：`const isCustomDriven = hasCustomParams && currentModelId.toUpperCase() !== 'LM-7A-01'`；
  3. 画布动点 $P$ 只能由 `param_t` 按 $(t-5)\times 0.5$ 偏移，而下方遥测距离和公式读取的是未更新的 `pos_p`。
* **运行实测复现数据**：
  ```
  输入状态：param_t = 8 (点 P 在数轴 x = 2.5), pos_p = 1 (默认值未联动)
  画布测量：PA = |2.5 - (-3)| = 5.50, PB = |2.5 - 3| = 0.50
  遥测公式计算：|PA - PB| = |(1 - (-3)) - (1 - 3)| = |4 - (-2)| = 2.00
  矛盾结果：屏幕同时显示 PA=5.50, PB=0.50，但距离差 |PA - PB| 却输出 2.00 (5.5 - 0.5 ≠ 2)！
  ```

### 3.2 `LM-7A-02`：动点完全锁死、中点公理失效、旋转解算查错对象、共线多边形退化
* **代码定位**：`src/modules/sandbox/morphControllers.ts` 第 455 行 `solveLM7A02`
* **缺陷机制**：
  1. **分点锁死**：解算器根本没有接收 `params.pos_p`，拖动动分点滑块时点 $P$ 纹丝不动；
  2. **公理违背**：$M_1$ 未联动更新，$M_2$ 被粗暴设为 `lenAB / 2`，忽视了 $M_2 = \frac{x_P + x_B}{2}$，双中点折半守恒实验完全失真；
  3. **旋转断连**：载体二（邻补角平分线）中动射线端点为 $C$，解算器硬编码寻找 `id === 'P'`（载体二根本没有 P 点），导致调节角度 $\alpha$ 时射线与角平分线完全静止；
  4. **多边形退化**：未配置特化模板，5 个共线点（$A, B, P, M_1, M_2$ 全在 $y=0$ 上）被 JSXGraph 通用降级逻辑强制闭合成封闭多边形，渲染出破损的折叠黑块。

### 3.3 `SB-QUADRATIC-VERTICAL-HEIGHT`（全局模型二）：模板路由错误与一维强制拍平
* **代码定位**：`src/modules/sandbox/configs/quadratic-vertical-height.ts` 第 9 行
* **缺陷机制**：
  1. 模板声明为 `canvas_template: 'axis'`。在 `SandboxRenderer.tsx` 中，`axis` 被归入一维数轴分支，**完全不绘制抛物线、不绘制铅垂线段 $PQ$、不绘制割线三角形 $\triangle PAB$**；
  2. 在拖拽监听中，`tpl === 'axis'` 触发了 `pt.setPosition(coordsMode, [pt.X(), 0])`，将试图在二维抛物线上移动的动点 $P$ **强行拍扁到 x 轴（$y=0$）**，导致铅垂高 $h \equiv 0$、面积恒为 0。

### 3.4 39 个概念沙盒：下划线导致 KaTeX 语法冲突
* **代码定位**：`src/modules/sandbox/invariants.ts` 第 255 行 `wrapFormulaLatex`
* **缺陷机制**：
  代码只要检测到字符串包含 `_`，便将其包装在 `$ ... $` 中交由 KaTeX 渲染。在 LaTeX 语法中 `_` 为下标符号，导致 `p_num / q_den = 1.50` 直接被渲染为：
  $$p_n um / q_d en = 1.50$$
  变量名严重穿帮，破坏了初中数学题目的严肃性。

### 3.5 8 个概念沙盒：滑块在渲染引擎中彻底无代码接入
* **缺陷机制**：
  在数据库中定义了前端控制条滑块，但在 `SandboxRenderer.tsx` 中从未声明对这些变量的监听与坐标计算。
  * `SB-KP003`：`val_a`（相反数）
  * `SB-KP008`：`val_base`（被开方数）、`zoom_level`（放大倍率）
  * `SB-KP034`：`x_sample`（一次函数采样点）
  * `SB-KP041`：`param_m`、`param_n`（抛物线区间最值）
  * `SB-KP042`：`param_k_level`（二次函数割线高度）
  * `SB-KP051`：`cond_mode`（全等三角形判定模式）
  * `SB-KP058`：`judge_criterion`（相似三角形判定基准）
  * `SB-KP066`：`convergence_path`（正方形逼近路径）

## 六、 底层通用计算与渲染机制架构缺陷评估

### 6.1 通用生命周期机制缺陷：频繁销毁与重建（Destroy-Recreate Overhead）
* **现状**：`SandboxRenderer.tsx` 中 `useEffect(..., [config, paramValues, xrayActive, locale])` 在每次 `paramValues` 变动时直接执行 `safeFreeBoardInstance` 销毁画布，随后调用 `JXG.JSXGraph.initBoard` 重建整块画布；
* **影响**：学生滑动滑块微调 0.1 时，整块黑板的 DOM、SVG 和事件全量销毁重建，导致**肉眼可见的白色闪烁（Flicker）**、**高频内存 GC 停顿**与**手势卡顿**；
* **改进结论**：必须建立**“结构变动（切沙盒）才重构，数值变动（挪滑块）仅 setPosition 增量更新”**机制。

### 6.2 通用降级机制缺陷：共线散点强制连成多边形（Collinear Polygon Degeneracy）
* **现状**：`SandboxRenderer.tsx` 通用降级逻辑认为“只要点数 $\ge 4$ 就执行 `board.create('polygon', primaryPoints)`”；
* **影响**：数轴动点模型（如 `LM-7A-01`、`LM-7A-02`、`SB-KP001` 等）中，多个点全部位于 $y=0$ 的直线上，JSXGraph 强行闭合共线点，渲染出破损的折叠黑块；
* **改进结论**：在多边形创建前增加**共线检测（Collinear Detector）**，若点集共线则退化为线段标尺，绝不创建多边形。

### 6.3 公式展示层缺陷：LaTeX 下标与内部变量名冲突（Underscore Syntax Conflict）
* **现状**：`invariants.ts` 中的 `wrapFormulaLatex` 检测到 `_` 就强制包裹 `$ ... $`，且未清洗内部变量名（如 `p_num / q_den`）；
* **影响**：覆盖了 39 个概念沙盒与多个跃迁模型，LaTeX 将 `_` 识别为下标符号，将公式渲染成 $p_n um / q_d en$；
* **改进结论**：在包裹数学定界符前，执行变量名字典置换，映射为标准数学字母（如 $\frac{p}{q}$、$k$、$a$）。
