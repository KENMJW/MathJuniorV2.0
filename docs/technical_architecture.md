# 全科核心素养提分系统 V2.0 — 技术架构设计文档 (Technical Architecture)

> 📌 **文档定位**：本文档为“全科核心素养提分系统 V2.0（初中数学模块）”的技术架构设计方案，明确纯静态 Web 运行环境、WASM 客户端数据库引擎、三端交互调度引擎、全栈多语言体系及无状态会话生命周期等核心技术实现机制。

---

## 1. 架构定位与设计哲学

本系统采用 **纯前端、纯静态、离线优先的 Web 架构 (Web-Only Static Architecture)**：
- **零服务端依赖**：无重型后端应用服务器、无后端 API 服务、无云端用户数据库。
- **全静态分发**：所有 HTML、CSS、JavaScript、WASM 编译模块、SQLite 离线数据包及矢量/位图多媒体资源均可通过标准 CDN 或静态 HTTP 服务器托管。
- **边缘计算与即时响应**：利用现代浏览器 WebAssembly 运行环境，将试题检索、图谱拓扑遍历、沙盒动力学计算完全下沉至客户端本地执行，实现毫秒级交互与极致隐私保护。

## 3. 设备智能识别调度引擎 (Device Detection & Router)

### 3.1 识别算法原理
系统坚决否定“简单 CSS 响应式媒体查询断点（Media Queries）自适应缩放”，而是在 JavaScript 应用启动阶段，通过硬件与视口特性综合判定设备类型并挂载独立控制器：

```javascript
export function detectDeviceProfile() {
  const isTouch = ('ontouchstart' in window) || (navigator.maxTouchPoints > 0);
  const isFinePointer = window.matchMedia('(pointer: fine)').matches;
  const isHoverable = window.matchMedia('(hover: hover)').matches;
  const width = window.innerWidth;
  const height = window.innerHeight;
  const aspectRatio = width / height;

  // 1. 手机端判定：触控屏、粗指针、小尺寸/竖长比
  if (isTouch && !isFinePointer && (width < 640 || (width < 900 && aspectRatio < 1))) {
    return 'MOBILE';
  }

  // 2. Pad端判定：触控屏、中大屏幕、通常为横屏或宽屏触控
  if (isTouch && width >= 640 && width <= 1366) {
    return 'TABLET';
  }

  // 3. PC端判定：精细鼠标指针、支持悬停、宽屏桌面环境
  if (isFinePointer && isHoverable && width > 900) {
    return 'DESKTOP';
  }

  return width < 768 ? 'MOBILE' : 'DESKTOP';
}
```

### 3.2 交互模式强制重写 (Override Mode)
系统在全局状态管理器中提供模式重写能力。学生或教师可于设置界面中手动选择“电脑模式”或“平板模式”，系统即时注销旧控制器并动态挂载目标设备控制器，无需重载页面。

## 4. 客户端 WebAssembly SQLite 数据库引擎

### 4.1 运行时选型与内存管理
- **运行环境**：采用 WebAssembly 编译的 SQLite 3（`@sqlite.org/sqlite-wasm` 或 `sql.js`）。
- **数据源载入**：
  1. 应用初始化时，通过 Web Worker 异步发起 `fetch('data/math_junior.db')`；
  2. 获取 `ArrayBuffer` 并导入 WebAssembly 虚拟内存空间；
  3. 建立只读连接（Read-Only Connection），所有 SQL 查询在独立 Worker 线程中执行，严禁阻塞前端主渲染线程。
- **性能指标**：
  - 完整数据库体积控制在 $20\text{MB} \sim 50\text{MB}$ 之间；
  - 单次复杂关联查询耗时严格控制在 $15\text{ms}$ 以内。

### 4.2 离线题库抽样与去重查询执行规范
在单知识点练习中，SQL 引擎执行严格的参数化查询：

```sql
-- 单考点靶向练习 3 题抽取查询
SELECT 
    question_id, 
    stem_zh, 
    options_json, 
    correct_option, 
    analysis_zh 
FROM questions 
WHERE primary_point_id = :current_point_id
  AND difficulty_level BETWEEN 1 AND 3
  AND question_type = 'single_choice'
  AND question_id NOT IN (/* 传入当前 Session 已展示的 ID 数组 */)
ORDER BY RANDOM() 
LIMIT 3;
```

## 5. 全栈多语言 (i18n) 国际化架构

### 5.1 双层解耦机制
1. **界面层 (UI Locales)**：
   - 维护纯静态语言包文件：`locales/zh-CN.json` 与 `locales/en.json`；
   - 包含菜单、操作提示、按钮文案及系统提示词。
2. **数据层 (Data Locales)**：
   - SQLite 数据库各表原生设计双语字段（如 `name_zh / name_en`，`content_zh / content_en`）；
   - 前端响应式上下文监听语言变化，自动投影读取目标语言字段。

### 5.2 数学排版统一架构：单入口入库清洗与单出口渲染网关 (Single Gateway)
为彻底杜绝大模型生成与真题录入时的 LaTeX 格式混乱、反斜杠转义丢失、语法死锁以及前端多处私自解析导致的**白屏崩溃（Blank Screen）**风险，系统确立“全生命周期单一风险点”的闭环网关架构：

```
【数据源头：大模型解析/题库抽取】 
              │
              ▼
┌────────────────────────────────────────────────────────┐
│ 🛡️ 唯一入库入口：MathIngestSanitizer (入库清洗校验门神) │
├────────────────────────────────────────────────────────┤
│ 1. 定界符绝对归一：强制将 \( \) 统一为 $...$, \[ \] 统一为 $$...$$ │
│ 2. 符号标准归一：统一 \times, \div, ^\circ, \triangle, \text{Rt}\triangle │
│ 3. 反斜杠转义加固：规范化反斜杠转义，杜绝入库反斜杠被吞问题   │
│ 4. Headless 语法预检拦截：用本地 KaTeX 试跑编译，报错直接拒绝 │
│    写入 SQLite，绝不让带病的公式脏数据污染离线数据库！       │
└──────────────────────────┬─────────────────────────────┘
                           │ 纯净数据落库 (SSOT)
                           ▼
                  [ SQLite: math_junior.db ]
                           │
                           ▼ 统一调用
┌────────────────────────────────────────────────────────┐
│ 🛡️ 唯一出库出口：<MathRenderer /> (全局统一渲染组件)   │
├────────────────────────────────────────────────────────┤
│ 1. 业务组件零侵入：全系统严禁任何模块私自调用原始 KaTeX 或 innerHTML │
│ 2. 零崩溃兜底沙箱 (Error Boundary)：throwOnError: false 配合错误捕获，│
│    异常时局部红字降级显示，宿主页面 100% 不白屏、不崩溃        │
│ 3. 全局 LRU 内存缓存：渲染过的公式片段直接复用，滑动零掉帧   │
│ 4. 主题色彩无缝继承：公式色彩统一继承 currentColor，明暗模式零延迟 │
│ 5. WebKit 离线字体保障：强制嵌入本地 WOFF2 矢量字体包，杜绝错位 │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
         【前端全场景安全上屏：模块一 / 二 / 三 / 四】
```

1. **唯一入库入口 (Ingestion Gateway)**：
   - 数据写入 `data/math_junior.db` 前，必须 100% 经过单点函数 `sanitize_and_verify_math()`；
   - 包含定界符归一、符号标准化、语法编译预检与 XSS 过滤；
2. **唯一出库出口 (Egress Gateway)**：
   - 界面所有展现数学公式的场景，全部由全局统一的 `<MathRenderer>` 组件承接；
   - 双语环境下 LaTeX 源码完全共用，仅语言文字对齐翻译，确保数学符号国际通用一致性。

## 6. 纯前端无状态会话模型 (Stateless Session)

### 6.1 隐私保护与零持久化设计
- 系统严格遵循“离线、断网可用、极致隐私”原则；
- **不使用 LocalStorage 或 IndexedDB 存储学生答题记录与错题数据**；
- 单次学习与练习的所有临时状态（已刷题目 ID 集合、实时得分、沙盒滑块数值）全部保存在当前浏览器页面上下文的内存 JavaScript 对象中；
- 页面刷新或标签页关闭，即刻释放全部会话数据，重置为纯净出厂状态。

## 7. 跨浏览器引擎兼容性技术标准

系统通过静态语法降级与 polyfill，实现全球主流引擎 100% 兼容：
- **Blink 引擎 (Google Chrome, Edge)**：启用 WebAssembly SIMD 加速，支持高性能 Canvas 渲染；
- **WebKit 引擎 (Apple Safari, iOS/iPadOS 全平台)**：
  - **避坑规范**：SVG 内部严格禁止使用 `<foreignObject>`，数学符号采用矢量路径化；
  - **触控屏**：严格配置 `touch-action: none;` 与 `-webkit-overflow-scrolling: touch;`；
- **Gecko 引擎 (Mozilla Firefox)**：保证 Canvas 与 SVG 复合图层的混合渲染精度与亚像素对齐。

### 9.3 学科业务自治与通用性边界 (Autonomous Domain Boundaries)
* **不可强求通用的部分（学科完全自主定义）**：
  * **功能模块**：初中数学总结出的“概念精讲、思维图谱、实验探究、实战测评”四大模块属于数学的最佳实践。物理/化学可能保留仿真实验与图谱，而语文/历史/英语等文科则完全由学科教研人员自主定义特色模块（例如历史的时空演进编年轴、史料实证大题，语文的文言文断句与整本书思辨阅读，无需生搬硬套数学沙盒）；
  * **数据库 Schema**：每个学科的 SQLite 数据库自主设计表结构，自给自足；
* **必须通用的部分（全平台全局同频）**：
  * **顶栏 Header 规范**：品牌 Logo、通知中心、多语言切换器、学习者档案胶囊；
  * **全局多语言 (i18n)**：在总门户或任意学科内切换语言，全系统无缝同频生效；
  * **设计 Token 与排版规范**：字体、字阶、主题基调与全局间距系统。
